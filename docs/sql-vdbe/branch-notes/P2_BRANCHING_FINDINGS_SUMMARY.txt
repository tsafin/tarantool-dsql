KEY PATTERN IDENTIFIED - P2-BASED BRANCHING
================================================================================

DANGEROUS PATTERN (Like OP_Clear bug):
  if (pOp->p2 > 0) {
      // Handle case 1
  }
  // ❌ MISSING else block! = Silent failure risk

SAFE PATTERN (Complete implementation):
  if (pOp->p2 > 0) {
      // Handle case 1
  } else {
      // Handle case 2
  }

WHY IT'S RISKY:
  - Both parameter values (P2>0 and P2==0) are VALID VDBE operations
  - If only one branch implemented, the other silently succeeds doing nothing
  - Example: DELETE FROM executed OP_Clear with P2==0, but handler did nothing
  - Result: Rows not deleted, no error reported - SILENT FAILURE
