### RISKY PATTERNS (6 handlers requiring attention)

#### 1. OP_Once (vdbe_ops_inline_medium_4.c) ⚠️ HIGH PRIORITY
- **Status**: SUSPICIOUS - Possible logic inversion
- **P2 Role**: Jump target when flag NOT set
- **Pattern**: `if (flag_is_set) return 1; else return 0;`
- **Issue**: Should initialize flag first, not check if already set
- **Used By**: Triggers and one-time initialization code

#### 2. OP_Last (vdbe_ops_cursor_nav.c) ⚠️ MEDIUM PRIORITY
- **Status**: ASSERTION CONSTRAINT - P2 value restricted
- **P2 Role**: Jump target when table empty
- **Pattern**: `if (p3==0 && p2>0 && res!=0) return 1;` with `assert(p2==0)` in else
- **Issue**: Strict assertion may reject valid bytecode
- **Used By**: Backward iteration through tables

#### 3. OP_Clear (vdbe_ops_inline_medium_5.c) ✅ FIXED
- **Status**: COMPLETE (fixed in 2fb0c16c34)
- **P2 Role**: Operation mode selector (TRUNCATE vs DELETE)
- **Pattern**: `if (p2 > 0) { truncate } else { delete with tracking }`
- **Was**: Missing else branch for P2==0
- **Now**: Both branches fully implemented
- **Used By**: All DELETE operations

#### 4. OP_MustBeInt (vdbe_ops_type.c) - NEEDS VERIFICATION
- **Status**: APPEARS COMPLETE but verify error handling
- **P2 Role**: Jump target on error
- **Pattern**: `if (conversion_fails) { if (p2!=0) jump; else error; }`
- **Issue**: Verify both paths execute correctly
- **Used By**: Type casting in VDBE programs

#### 5. OP_GetItem (vdbe_ops_inline_medium_7.c) ❌ INCOMPLETE STUB
- **Status**: NON-FUNCTIONAL PLACEHOLDER
- **P2 Role**: Container register (source), NOT branching
- **Pattern**: Null check only, no extraction logic
- **Issue**: TODO comment indicates unimplemented

#### 6. OP_OffsetLimit (vdbe_ops_inline_medium_6.c or vdbe_dispatch_wrapper.c)

## SAFE PATTERNS (21 handlers verified)

### Return Code-Based Branching (12 handlers)
These handlers return different codes to signal dispatcher action. **Pattern: SAFE**

**List**:
1. **OP_Rewind** - Returns 0 (not empty) or 1 (empty, jump P2)
2. **OP_Last** - Returns 0 (continue) or 1 (empty, jump P2)
3. **OP_Next** - Returns 0 (more rows, jump P2) or 1 (exhausted)
4. **OP_Prev** - Returns 0 (more rows backward, jump P2) or 1 (exhausted)
5. **OP_NextIfOpen** - Delegates to OP_Next
6. **OP_PrevIfOpen** - Delegates to OP_Prev
7. **OP_SorterNext** - Returns 0 (more rows) or 1 (exhausted, jump P2)
8. **OP_SorterCompare** - Returns 0 (match) or 1 (different, jump P2)
9. **OP_SeekLT/LE/GT/GE** - Returns 0/1/2 to indicate seek result
10. **OP_Found** - Returns 0 (continue) or 1 (found, jump P2)
11. **OP_NotFound** - Returns 0 (not found, jump P2) or 1 (found)
12. **OP_NoConflict** - Returns 0 (continue) or 1 (jump P2)

**Safety**: All follow same pattern - return value determines jump, P2 is target address.

### Flag-Based Branching (8 handlers)
These check P5 flags, NOT P2 value. P2 used as output or jump target. **Pattern: SAFE**

**List**:
1. **OP_Eq** - P5 flag SQL_STOREP2 controls: store in P2 OR jump P2
2. **OP_Ne** - Same pattern as OP_Eq
3. **OP_Lt** - Same pattern as OP_Eq
4. **OP_Le** - Same pattern as OP_Eq
5. **OP_Gt** - Same pattern as OP_Eq
6. **OP_Ge** - Same pattern as OP_Eq
7. **OP_Compare** - Always stores result in p->iCompare, continues
8. **OP_IsNull/NotNull** - Flag-based branching (not P2 value)

**Safety**: Flag controls branching, not P2 value. Both paths properly implemented.

### Data Flow (3 handlers)
These use P2 as data operand, no conditional branching. **Pattern: SAFE**

**List**:
1. **OP_AddImm** - P2 is immediate value to add: `pIn1->u.u += pOp->p2;`
2. **OP_Sequence** - P2 is output register, no branching
3. **OP_Fetch** - P2 is field index, no branching

**Safety**: No conditional logic, straightforward data transfer.

### HIGH (Should Fix)

#### OP_Once - Logic Inversion
```c

    return 1;  /* Signal jump to P2 */
}

```
**Problem**: Where is the flag SET? Normal pattern would be:
1. Check flag is CLEAR → set it and jump
2. Subsequent calls: flag is SET → skip (jump)

**Verification Needed**:
```bash

```

### MEDIUM (Should Audit)

#### OP_Last - Assertion Constraint
```c
if (pOp->p3 == 0 || !sqlCursorIsValidNN(pCrsr)) {
    // ... seek logic ...
    if (pOp->p2 > 0 && res != 0)
        return 1;  /* Jump to P2 */
} else {
    assert(pOp->p2 == 0);  ← STRICT
}
```
**Problem**: Assertion requires P2==0 when P3!=0. May reject valid bytecode.

**Verification Needed**: Check SQL compiler semantics for OP_Last parameter generation.

#### OP_MustBeInt - Error Handling
```c
if (conversion_fails) {
    if (pOp->p2 != 0)
        return 1;  /* Jump to P2 */
    diag_set(...);
    return -1;  /* Error */
}
```
**Verify**: Both paths work correctly. Compare with inline dispatcher.

### LOW (Probably Safe)

All remaining handlers (20+) follow established patterns with proper branching.

## Pattern Classification Summary

### Pattern 1: Return Code Branching
```
Handler Return:
  0 → Continue to next opcode
  1 → Jump to P2 (or perform action indicated by opcode semantics)
  -1 → Error occurred
```
**Safety**: HIGH - Very clear, easy to verify

### Pattern 2: Flag-Based Branching
```
Check P5 flags (not P2 value):
  if (flag_set) → one behavior
  else → different behavior
Both paths fully implemented.
```
**Safety**: HIGH - Proper binary paths, clear flag semantics

### Pattern 3: Parameter-Driven Branching (DANGEROUS)
```
Check P2 value directly:
  if (pOp->p2 > 0) → behavior A
  else/if (pOp->p2 == 0) → behavior B
MUST implement BOTH paths completely!
```
**Safety**: MEDIUM - Easy to forget else block (see OP_Clear)

### Pattern 4: Data Flow (No Branching)
```
P2 is input/output register:
  No conditional logic
  Direct data transfer
```
**Safety**: HIGH - No control flow to verify
